# Broker credentials are persisted encrypted, decrypted only transiently in worker memory

The worker logs in to KGI/Fubon unattended, before market open every trading day, so credentials can't require manual re-entry without breaking that goal. KGI's national ID/password and Fubon's API key/secret are Fernet-encrypted at rest in `broker_credentials`, keyed by a `BROKER_CRED_KEY` env var (never committed, present only on the web service and worker); decrypted values exist only as local variables during the login call, never logged or written anywhere in decrypted form. KGI's cert is obtained by the user from KGI's 憑證中心 (Certificate Center) and installed with a one-time CLI step — `./KGI_CGCrypt genDat`, supplying the certificate file path, account, and password — done manually, once per account, outside the app; a self-service cert-generation flow isn't worth building for something done once.

Credential entry is a self-service, in-app UI (matching issues #21/#24/#25): any logged-in user can add a KGI or Fubon credential, scoped to their own `g.user.id`, which grows the shared Connection Pool's capacity rather than being tied to a fixed two-account setup. Since every user of this app is trusted (the same two-person, coordinate-directly model as the shared Watchlist in `docs/adr/0005`), self-service entry doesn't need an approval step or admin gate — it's built for the case where either of you acquires another broker account later and just wants to add it, not only the initial one-time setup.
