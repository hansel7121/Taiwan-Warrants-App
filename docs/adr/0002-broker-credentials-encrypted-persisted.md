# Broker credentials are persisted encrypted, decrypted only transiently in worker memory

The worker logs in to KGI/Fubon unattended, before market open every trading day, so credentials can't require manual re-entry without breaking that goal. KGI's national ID/password and Fubon's API key/secret are Fernet-encrypted at rest in `broker_credentials`, keyed by a `BROKER_CRED_KEY` env var (never committed, present only on the web service and worker); decrypted values exist only as local variables during the login call, never logged or written anywhere in decrypted form. KGI's CA cert is generated by the user manually, one time, outside the app, and just uploaded — a self-service cert-generation flow isn't worth building for something done once per account.
