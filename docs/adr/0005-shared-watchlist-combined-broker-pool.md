# Watchlist and connection capacity are shared across users, not isolated per user

Two people use this app, one with a KGI account and one with a Fubon account. Rather than each running an independent, isolated live scanner limited to their own broker's capacity, the two Broker Accounts' capacity is combined into one Connection Pool covering a single shared Watchlist — maximizing the total number of warrant codes watchable live, since the two brokers' subscription quotas don't compete with each other. Overflow between brokers is simplest-order (fill one's connections, then the other's); which broker carries which code doesn't affect correctness.

Consequences: the Watchlist is one shared, freely-editable list rather than a per-user one (no access control — solved socially, not with a permission layer, since it's two people who already coordinate directly). Arb Signals are correspondingly global/server-only (no per-user scoping), matching the existing `arb_suggestions` precedent. Broker credentials remain per-user (self-service, each person manages only their own Broker Account) even though their *effect* — subscription capacity — is pooled. Worker Status is tracked per Broker Account so a single broker's disconnect is visible as a partial capacity loss, not a full outage.
