# Worker connection resilience: capacity-tier pooling, auto-reconnect, and status as shared state

Because the intended Watchlist is large, the worker's Connection Pool spreads subscribed codes across multiple broker connections per the account's Capacity Tier — KGI's tier is manually configured (starting at base: 30 symbols/connection, 2 connections), Fubon's is fixed (200 symbols/connection, 5 connections) with no tier concept. On disconnect, the worker auto-reconnects with backoff and resubscribes from the persisted Watchlist.

Connection/health state is written to a `worker_status` table rather than embedded only in a one-off alert call, so the web UI's status indicator and the on-disconnect notifications are both just consumers of that same state — and a future monitoring agent (e.g. Hermes) can read the same table instead of requiring its own bespoke integration. Two notification channels fire on disconnect, independently: a Slack Incoming Webhook (`SLACK_WEBHOOK_URL`) and an ntfy.sh push (topic URL in an env var) — redundant on purpose, since a dropped connection during trading hours is exactly the kind of event where a single channel being unavailable (Slack down, phone not receiving push) shouldn't mean no alert at all.
